# Blender 5.2 LTS fact sheet - Easy Text phase 3/4 (researched 2026-10-11)

Evidence tags: **[doc]** = stated in Blender 5.2 manual / API docs / release notes; **[run]** = executed headless in the real `bpy 5.2.2 LTS` (PyPI wheel, Python 3.13, factory prefs; test scripts in `scratchpad/research/tests/`); **[src]** = read in Blender source branch `blender-v5.2-release` (raw.githubusercontent.com/blender/blender/blender-v5.2-release/...); **[inf]** = inferred, not proven. Not testable here: EEVEE (no libEGL), UI drawing, viewport selection.
Docs: `docs.blender.org/manual/en/latest/` and `/api/current/` currently resolve to "Blender 5.2 LTS" (checked page titles); URLs below use the explicit `/5.2/` paths.

## Top gotchas (read first)
1. **GN modifier inputs API changed in 5.2**: `mod["Socket_2"]` now raises TypeError. Use `mod.properties.inputs.<identifier>.value`. A write did NOT re-evaluate headless until `obj.update_tag()` was called (Q10).
2. GN **can** instance Light objects (Object Info "As Instance" / Collection Info); Cycles renders them. `Realize Instances` deletes them. A GN-instanced Camera can **not** be `scene.camera` (Q1, Q3).
3. `Object.camera_fit_coords` silently returns `(Vector(0,0,0), 1.0)` with <2 points [run], uses the *evaluated* camera's current rotation, and ignores `resolution_percentage` (Q4).
4. Extension ToS 1.2 says bundled binary assets incl. **fonts must be CC0**; one listed extension bundles OFL fonts anyway (Q12).
5. `Action.fcurves` no longer exists (layered actions); `Curve.use_path` must stay True for Follow Path (Q5).
6. No API to register an extension asset library; `asset_libraries.new()` works but edits user prefs; real extensions append node groups on demand (Q8).

# A. Light rigs with Geometry Nodes
**1. Instancing Lights** - YES.
- Manual: Object Info "As Instance" "allows instancing non-geometry object types, because the output will contain an instance of the object" [doc]. https://docs.blender.org/manual/en/5.2/modeling/geometry_nodes/input/scene/object_info.html
- Mesh to Points -> Instance on Points(Instance = Object Info(light, As Instance=True)): `depsgraph.object_instances` listed 3 `LIGHT` instances at the point positions [run]. Collection Info works too: whole collection (every light at every point), or `Separate Children`+`Reset Children`+`Pick Instance`+`Instance Index` chooses a different template light per point (children come sorted by name; index wraps) [run].
- Cycles CPU render: mean pixel 0.0 without lights vs 3.91 with GN-instanced lights, also when the template has `hide_render=True` or sits in an excluded collection (so the template can be hidden) [run]. EEVEE: `Instance::object_sync` handles `OB_LAMP` for every depsgraph object ref incl. dupli instances, and 5.2 adds light camera-ray visibility [src] https://raw.githubusercontent.com/blender/blender/blender-v5.2-release/source/blender/draw/engines/eevee/eevee_instance.cc ; not render-tested.
- Limits: all instances share the template's `Light` datablock (colour/power/spot size/shadow are identical); per-point variation is only transform (loc/rot/scale) or choosing among templates via Pick Instance [run]. `Realize Instances` leaves nothing (lights vanish) [run]. Instances are not separate selectable objects; viewport light overlay is drawn per object ref [src overlay_instance.cc] (selection = [inf]). With "Original" transform space the template's own transform is ignored (instance matrix = point only) [run]; "Relative" keeps its pose relative to the modifier object [doc].
- Also 5.2: Empty objects can now carry GN modifiers [doc] https://developer.blender.org/docs/release_notes/5.2/geometry_nodes/

**2. Aim rotation nodes** [run: bl_idname / sockets introspected in bpy 5.2.2]
- `FunctionNodeAlignRotationToVector` ("Align Rotation to Vector"): inputs `Rotation`(rot), `Factor`, `Vector`; output `Rotation`; props `axis` ('X','Y','Z'; default 'Z'), `pivot_axis` ('AUTO','X','Y','Z'; default 'AUTO').
- `FunctionNodeAxesToRotation`: inputs `Primary Axis`, `Secondary Axis` (vectors); output `Rotation`; props `primary_axis` (X/Y/Z, default Z), `secondary_axis` (X/Y/Z, default X).
- `FunctionNodeRotateRotation`: inputs `Rotate By`, `Rotation`; prop `rotation_space` ('GLOBAL','LOCAL'). There is no "Look At" node in 5.2.
- Aim recipe, verified numerically (dot(-Z, dir_to_target) = 1.0 for 4 points): `Position` - `target location` (Vector Math SUBTRACT) -> Align Rotation to Vector (axis Z) -> Instance on Points `Rotation`. Lights/spots/suns/areas emit along local -Z, hence position-minus-target [run]. Use Object Info(target) with `transform_space='RELATIVE'` if the emitter object is transformed: "Original" gives world-space location, Position field is object-local [doc, same manual page; not numerically tested].
- Instance on Points sockets: Points, Selection, Instance, `Pick Instance`, `Instance Index`, Rotation, Scale -> Instances. Object Info: Object, `As Instance` -> Transform, Location, Rotation, Scale, Geometry. `GeometryNodeSetInstanceTransform`, `GeometryNodeRotateInstances` also exist [run].

**3. Camera instanced via GN as render camera** - NO [run]. The instance appears in `depsgraph.object_instances` as `CAMERA`, but `scene.camera = inst.object` (evaluated object) leaves `scene.camera` None; `inst.object.original` is the template at its own transform. Instances are not in `bpy.data.objects`. Use a real camera object (Q5 constraints). 

# B. Camera framing and orbit
**4. Fit bbox to frame**
- Signature [doc+src] https://docs.blender.org/api/5.2/bpy.types.Object.html#bpy.types.Object.camera_fit_coords : `Object.camera_fit_coords(depsgraph, coordinates) -> (co: Vector, scale: float)`; `coordinates` = flat float sequence `[x0,y0,z0,x1,...]` in **world space**. `co` = new world location; `scale` = ortho scale (perspective returns 1.0 - ignore).
- Behaviour [src] https://raw.githubusercontent.com/blender/blender/blender-v5.2-release/source/blender/blenkernel/intern/camera.cc : uses the *evaluated* camera (world matrix incl. parent/constraints), `lens`, `sensor_fit`, sensor size, shift, and scene `resolution_x/y` + pixel aspect (NOT `resolution_percentage`). Orientation is kept; only position (and ortho scale) is solved, with lateral shift for a tight fit. The C bool result is dropped by the RNA wrapper, so <2 points = silent `(0,0,0), 1.0` [run]. Call `view_layer.update()` after changing rotation, pass `bpy.context.evaluated_depsgraph_get()`. With a Track To constraint the orientation depends on location, so fit with a constraint-free helper camera/formula then copy the location.
- Verified use [run]: set `cam.rotation_euler`, `view_layer.update()`, `co, s = cam.camera_fit_coords(dg, flat)`, `cam.location = co`, ortho: `cam.data.ortho_scale = s`. Result touched x=0 and x=1 of `world_to_camera_view` (landscape/portrait/square, AUTO/HORIZONTAL/VERTICAL, persp+ortho; ortho overshoot <=0.3%).
- Manual formula (centered camera on direction `u` from bbox centre C; matched camera_fit_coords within 0.2-2%, slightly conservative) [run, from camera.cc `BKE_camera_params_compute_viewplane`]:
  `rx,ry = res_x*pixel_aspect_x, res_y*pixel_aspect_y`; `fit = sensor_fit if != 'AUTO' else ('HORIZONTAL' if rx>=ry else 'VERTICAL')`; **`S = sensor_height if camera.sensor_fit=='VERTICAL' else sensor_width`** (AUTO always uses sensor_width, even for portrait); `t = S/(2*lens)`; HORIZONTAL: `tx=t, ty=t*ry/rx`; VERTICAL: `ty=t, tx=t*rx/ry`. For each corner `q=P-C`: `D = max(D, q.u + |q.right|/tx, q.u + |q.up|/ty)`; camera at `C + u*D*margin`. Ortho: `scale = 2*max(hx, hy*rx/ry)` (HORIZONTAL) or `2*max(hy, hx*ry/rx)` (VERTICAL), hx/hy = max |q.right|, |q.up|. Camera.angle_x/angle_y (rad) exist but ignore fit.
- Source for sensor semantics: https://docs.blender.org/api/5.2/bpy.types.Camera.html [doc].

**5. Follow Path + Track To from Python** [run + src https://raw.githubusercontent.com/blender/blender/blender-v5.2-release/source/blender/blenkernel/intern/constraint.cc]
```python
fp = cam.constraints.new('FOLLOW_PATH'); fp.target = path_obj          # Curve object
fp.use_fixed_location = True; fp.use_curve_follow = False             # offset_factor drives position
tt = cam.constraints.new('TRACK_TO'); tt.target = target_empty
tt.track_axis = 'TRACK_NEGATIVE_Z'; tt.up_axis = 'UP_Y'                # also the .new() defaults
cam.keyframe_insert(data_path=f'constraints["{fp.name}"].offset_factor', frame=1)   # key 0.0, then 1.0
```
- Names: `FollowPathConstraint.use_curve_follow`, `.use_fixed_location`, `.offset_factor` (float, RNA range unbounded, UI 0..1), `.offset` (frames, only used when NOT fixed), `.forward_axis` (default FORWARD_Y), `.up_axis` (UP_Z), `.use_curve_radius` [doc] https://docs.blender.org/api/5.2/bpy.types.FollowPathConstraint.html . TrackTo: `target, track_axis, up_axis, use_target_z` [doc].
- Keyed 0->1 over frames 1..121 on a radius-5 circle: camera sat at the expected quarter points at 0/25/50/75/100 %, -Z facing the target (dot 1.0) [run].
- `Curve.path_duration` is NOT needed with `use_fixed_location=True` (changing it to 500 changed nothing); it only scales `Curve.eval_time` mode [run/src]. `Curve.use_path` IS needed: default False for `bpy.data.curves.new`, auto-set True when the constraint target is assigned from Python; forcing it False sent the camera to the origin [run]. Set `curve.use_path = True` explicitly for safety.
- 5.2 animation API: `Action.fcurves` is gone. After keying: `strip = ob.animation_data.action.layers[0].strips[0]; fc = strip.channelbag(ob.animation_data.action_slot).fcurves[0]` (or `bpy_extras.anim_utils.action_get_channelbag_for_slot`) then `kp.interpolation='LINEAR'` (default is BEZIER) [run]. New pref "Only Insert Available" is default-on in 5.2 [doc: https://developer.blender.org/docs/release_notes/5.2/animation_rigging/] but did not block `keyframe_insert` creating new F-curves [run]. For a seamless loop key factor 1.0 on frame_end+1 (cyclic path) [inf].

# C. Extension packaging for 5.2
**7. blender_manifest.toml** https://docs.blender.org/manual/en/5.2/advanced/extensions/getting_started.html [doc] + validator in `scripts/addons_core/bl_pkg/cli/blender_ext.py` [src/run]
- Required: `schema_version="1.0.0"`, `id` (python identifier, no `__`, no leading/trailing `_`), `version` (semver), `name`, `tagline` (<=64 chars, must not end in punctuation; `)]}` ok), `maintainer`, `type` ("add-on" or "theme" only), `blender_version_min` (strict build wants 3 numbers: "5.2.0"; "5.2" is rejected), `license` (list). Docs: "use at least 4.2.0".
- Optional: `blender_version_max` (exclusive: "does not support"), `website`, `copyright` (["2026 Name"]), `tags`, `platforms` (windows-x64, windows-arm64, macos-x64, macos-arm64, linux-x64; omit = all), `wheels` (forward slashes, `./wheels/x.whl`, python 3.13), `[permissions]` table, `[build]`. Empty values are not allowed (omit the key). Do not declare `[build.generated]`.
- `license`: docs require "SPDX:" prefix; add-ons must be GPL-3.0-or-later (https://docs.blender.org/manual/en/5.2/advanced/extensions/licenses.html). Listed add-ons: 1159 of 1236 use exactly `["SPDX:GPL-3.0-or-later"]`, 64 `GPL-2.0-or-later`, some add `SPDX:MIT`/`CC0-1.0`/`Zlib` [index]. The CLI does NOT check the prefix (a bare "GPL-3.0-or-later" passed `validate`), the server does [run].
- `[permissions]` keys: files, network, clipboard, camera, microphone; value = one short sentence, <=64 chars, no final period. `network` additionally requires respecting `bpy.app.online_access` https://docs.blender.org/manual/en/5.2/advanced/extensions/addons.html . 59 of 1236 listed add-ons declare network.
- `tags` (add-ons, 5.2 `_bpy_internal/extensions/tags.py` + https://docs.blender.org/manual/en/5.2/advanced/extensions/tags.html): 3D View, Add Curve, Add Mesh, Animation, Bake, Camera, Compositing, Development, Game Engine, Geometry Nodes, Grease Pencil, Import-Export, Lighting, Material, Mesh, Modeling, Node, Object, Paint, Physics, Pipeline, Render, Rigging, Scene, Sculpt, Sequencer, System, Text Editor, Tracking, User Interface, UV. (No Text/Font tag.) Run through the `blender` binary, build/validate use Blender's bundled tag list (`--valid-tags=""` disables) [doc]; my direct run of `blender_ext.py` had no tag list and accepted a bogus tag [run].
- `[build]`: `paths` (include list) XOR `paths_exclude_pattern` (gitignore syntax; default `["__pycache__/", ".git", "*.zip"]`); both together is an error [doc+src]. Commands: `blender --command extension build [--source-dir --output-dir --split-platforms --valid-tags]`, `... validate` https://docs.blender.org/manual/en/5.2/advanced/command_line/extension_arguments.html . A sample manifest built successfully with the 5.2 tool [run].
- Extension code must use relative imports and `__package__` (no hard-coded module name; module lives under `bl_ext.<repo>.<id>`) [doc, addons page]. Write user data to `bpy.utils.extension_path_user(__package__, path="", create=True)`, never into the add-on dir [doc].

**8. Shipping node-group assets** 
- No 5.2 API registers an extension-owned asset library: `bpy.utils` has no `register_asset_library`; no "user_default" library; manual says a library is one "registered in the Preferences" (https://docs.blender.org/manual/en/5.2/files/asset_libraries/introduction.html) [doc/run]. Manifest `type` cannot be an asset bundle (only add-on/theme) [src].
- `bpy.context.preferences.filepaths.asset_libraries.new(name=, directory=)` works in 5.2 [run] (https://docs.blender.org/api/5.2/bpy.types.AssetLibraryCollection.html) but writes the user's preferences (marks them dirty, persists after uninstall, default `import_method='PACK'`), and 5.2 changed list indices (two new entries "All Libraries"/"Essentials" shift `active_asset_library`) [doc: https://developer.blender.org/docs/release_notes/5.2/python_api/]. No guideline explicitly forbids it, but ToS 3.9 forbids tampering with "sensitive user data" -> treat as discouraged [inf]. Of ~125 asset/preset/lighting extensions I downloaded and grepped, none call `asset_libraries.new`; they only read the list. If wanted, do it from an explicit operator/button, not in `register()`.
- Recommended (what real extensions do, e.g. `t3d_gn_presets` ships `t3d_nodes.blend`, permission `files = "Append node-groups from source file"`): append on demand [run]:
```python
path = os.path.join(os.path.dirname(__file__), "assets", "easytext.blend")      # read-only is fine
with bpy.data.libraries.load(path, link=False, reuse_local_id=True) as (src, dst):
    dst.node_groups = [n for n in ("ET_LightRig",) if n in src.node_groups]
```
  `reuse_local_id=True` prevented the `.001` duplicate on the second call (plain append duplicated) [run]; also available: `assets_only`, `clear_asset_data`, `pack`, `create_liboverrides`. New in 5.2: `input.libraries` info [doc]. Add `use_fake_user=True` if the group must survive purge. https://docs.blender.org/api/5.2/bpy.types.BlendDataLibraries.html

**10. GN modifier inputs in 5.2** (breaking change) https://developer.blender.org/docs/release_notes/5.2/python_api/ [doc], behaviour [run], implementation [src: nodes/intern/geometry_nodes_srna.cc]
```python
ident = next(i.identifier for i in ng.interface.items_tree
             if i.item_type == 'SOCKET' and i.in_out == 'INPUT' and i.name == "Radius")   # e.g. "Socket_3"
slot = getattr(mod.properties.inputs, ident)      # runtime RNA PropertyGroup
slot.value = 2.0                                  # float/int/bool/vector/colour/str/Object/Collection/Material/Font(VectorFont)
slot.type = 'ATTRIBUTE'; slot.attribute_name = "x"  # only sockets that support fields (enum VALUE/ATTRIBUTE); Bool also has .layer_name
mod.properties.outputs.<ident>.attribute_name = "out"
obj.update_tag()                                  # needed: without it evaluated geometry stayed stale until an object tag/modifier toggle
```
- `mod[ident]` read -> TypeError "this type doesn't support IDProperties"; write -> TypeError. `hasattr(mod,'inputs')` False (only `mod.properties.inputs`). [run]
- Your finding `mod.properties.inputs[id]['value']` DOES work for read and write (IDProperty view of system properties; returned 8.0 after set) but is undocumented, skips RNA, and a write likewise did not re-evaluate. Prefer attribute access [run]. Release note 5.0 says dict access to bpy.props-defined storage is unsupported in general.
- Identifiers are `Socket_N` (panels consume numbers, so ids are not contiguous) and stable under rename; names may repeat across panels, so look up by identifier. `mod.is_input_used(ident)`, `mod.is_input_visible(ident)` exist; `mod.properties.panels.open_<panel_id>` booleans. Keyframe path `modifiers["GN"].properties.inputs.Socket_3.value` works with `obj.keyframe_insert(...)` [run]. Old animation paths are backward-compatible only (commit 1561c1ea4a message).
- `Compare`/`Random Value` socket identifiers changed in 5.2 [doc] - re-check any hard-coded identifiers of those nodes. 5.1 added Font socket and String to Curves options as sockets; 5.2 adds Font input nodes [doc].

**11. System fonts** 
- No bpy API lists installed fonts: `bpy.app` has no font attribute, `bpy.ops.font.*` has only open/unlink/text ops, `blf` has no listing [run]. Add-ons scan OS dirs and load with `bpy.data.fonts.load(path, check_existing=True)` (signature [doc] https://docs.blender.org/api/5.2/bpy.types.BlendDataFonts.html). `preferences.filepaths.font_directory` is only a file-browser default; its default is the OS dir: Windows `CSIDL_FONTS` (`C:\Windows\Fonts`), macOS **`~/Library/Fonts`** (not `/Library/Fonts`), Linux `/usr/share/fonts` [src: blenkernel/intern/appdir.cc `BKE_appdir_font_folder_default`, run on Linux].
- Scan lists used by the published Font Selector extension (v3.2.2, min 5.0, permission files): Linux `/usr/share/fonts`, `/usr/local/share/fonts`, `~/.local/share/fonts`, `~/.fonts`; Windows `C:\Windows\Fonts`, `%LOCALAPPDATA%\Microsoft\Windows\Fonts`; macOS `~/Library/Fonts`, `/Library/Fonts`, `/System/Library/Fonts`. https://extensions.blender.org/add-ons/font-selector/ [doc/inspected zip]. It bundles `fonttools` as a wheel to read family names; in 5.2 Blender itself names the datablock from the font metadata (e.g. "DejaVu Serif Bold", "Inter Variable Regular"), not the filename [run].
- VectorFont [run]: `.filepath` = absolute path for loaded fonts, `'<builtin>'` for the default; `bpy.data.fonts["Bfont Regular"]` appears only after the first Text object/curve is created (factory-empty file has none) and fills all four slots (`font`, `font_bold`, `font_italic`, `font_bold_italic`). Loaded fonts are NOT packed (`packed_file None`; call `.pack()` to embed). `load(check_existing=True)` returns the same datablock on repeat; a bad path raises RuntimeError. Assigning `curve.font = vf` changed text width as expected (4.786 -> 4.004). woff2 loads (Blender ships `Inter.woff2`, `DejaVuSansMono.woff2` + Noto in `bpy.utils.system_resource('DATAFILES', path='fonts')`) - usable without bundling anything.
- 5.1/5.2 notes: new fill algorithm for overlapping outlines (5.1), better combining characters but no full shaping (5.2) https://developer.blender.org/docs/release_notes/5.2/modeling/ [doc].

**12. Review rules** (ToS "Last updated 10 August 2026" https://extensions.blender.org/terms-of-service/ ; guidelines https://developer.blender.org/docs/handbook/extensions/addon_guidelines/) [doc]
- Fonts/assets: ToS 1.2 "Binary files or other types of assets included in the extension (images, SVG files, fonts, etc.) must be licensed as Public Domain (CC0)"; same in manual Licenses page. So OFL fonts are NOT allowed by the text. Practice: `latex_text_generator` (listed, GPL-3.0-or-later) bundles STIX Two Math (OFL) and Latin Modern (GUST) with licence files in `fonts/` [inspected zip] - reviewer tolerance is [inf]. Safe options: CC0/public-domain fonts only, Blender's own bundled fonts via `system_resource`, or system fonts. A bundled `.blend` of node groups counts as an asset (CC0) - `t3d_gn_presets` ships one under GPL; credit third parties in `copyright`.
- Network: only with `[permissions] network` + reason, and only when `bpy.app.online_access` is True (ToS 4.1/4.2/4.5; guidelines). Easy Text needs none. Opening a browser from a button needs neither (4.4).
- Other: add-on code GPL-3.0-or-later (1.1); name must not contain "Blender" (2.1); code fully Python, no obfuscation, no pre-compiled deps (3.5/3.6); no remote code, no required external downloads, no dependency on other extensions (5.1-5.3); must not modify other add-ons/modules (3.9, guidelines); no ads/donation buttons in the UI (6.1); self-contained, wheels only unmodified from PyPI, no writing into own dir (use `extension_path_user`).
- Size: no 5.2 doc states a limit. Maintainer said 200 MB (June 2024, https://projects.blender.org/infrastructure/extensions-website/issues/130 via API); largest listed archive today is 191 MB; median 28 KB [index]. `--split-platforms` for big wheels. [inf] still 200 MB.

# D. Scene/animation helpers
**13. Scene Time node** (`GeometryNodeInputSceneTime`, outputs `Seconds`, `Frame`; manual calls the second "Frames") https://docs.blender.org/manual/en/5.2/modeling/geometry_nodes/input/scene/scene_time.html [doc]
- Source `node_geo_input_scene_time.cc` + `scene.cc` [src]: `Frame = (frame_current + subframe) * framelen`, `Seconds = Frame / (fps / fps_base)`; framelen = Time Stretching `render.frame_map_new / frame_map_old`. Verified [run]: fps 24 -> frame 10 gives Frame 10.0, Seconds 0.4167; subframe 0.5 gives 12.5; stretching old 100/new 200 at frame 24 gives Frame 12.0 / Seconds 0.5; new 50 gives 48.0 / 2.0; fps 30 frame 30 -> Seconds 1.0. Not offset by `frame_start` (frame 1 = 1.0). NLA strip remapping does not apply (node reads scene time only) [src/inf]. Non-integer values appear during motion blur sub-frames [doc].
- 5.2 adds a "Scene Frame" default for group inputs [doc 5.2 GN notes].
- Simulation zone: no caveat if Scene Time only drives transforms outside a zone. Links from outside into a zone are "re-evaluated every step"; zones evaluate only while the frame advances and are cached, so jumping with `frame_set` skips simulation steps [doc: .../simulation/simulation_zone.html; inf for the jump consequence].

**14. Headless frame change** [run + doc https://docs.blender.org/api/5.2/bpy.types.Scene.html]
- `scene.frame_set(n, subframe=0.0)` "updating all objects and view layers immediately" and fires `frame_change_*` handlers; after it `bpy.context.evaluated_depsgraph_get()` returned GN output for the new frame (Scene Time drove vertex x correctly at frames 10/12.5/24/30).
- Plain `scene.frame_current = n` also re-evaluated on the next `evaluated_depsgraph_get()` in my test but did NOT fire handlers - prefer `frame_set`. `bpy.ops.render.render()` evaluates at the current frame.
- Reading evaluated data: `ev = obj.evaluated_get(bpy.context.evaluated_depsgraph_get())`. Modifier-input writes need `obj.update_tag()` first (see Q10).
